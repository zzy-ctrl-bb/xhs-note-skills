# 视频转图文笔记

运行条件包括本地文件和命令执行权限、读图能力、Python 3.9+、Pillow、ffmpeg 和 ffprobe。免费链接入口需要 Node.js 22+、桌面 Chrome 与网络；TikHub 备用入口另需使用者的凭据和调用授权。

当前 Skill 的交付物是一个可独立使用的文件夹。可读图、可运行本地命令的助手负责理解内容。命令均从本 Skill 目录运行；工作目录由调用者选择，使用属于当前作品的独立目录。

## 取得原片

- 已有本地视频时，可直接交给 `draft.py prepare`。若还需要下载工具的文件校验和本地回执，使用 `python3 scripts/download_source.py --video "原片.mp4" --out "下载工作目录"`。
- 有分享链接时，优先走普通官网播放器。首次执行 `npm ci --prefix browser`，然后 `node browser/download.mjs --url-file "分享链接文本文件" --out "新下载目录"`。也可用 `--url` 传单条分享文案。此入口在独立 Chrome 会话中匿名打开作品，只接受可正常播放、对应唯一可验证媒体文件且允许保存的内容。成功后取 JSON 中的 `video` 路径继续；同一来源与输出目录可复用已校验的原片。
- 官网播放器未能提供完整媒体、但持有人允许尝试付费服务时，使用 `python3 scripts/download_source.py --url "单条分享内容" --out "下载工作目录"`。通过进程参数传链接；调用者使用参数列表或正确引用，避免分享文案被解释成命令。
- 对方已同意本条视频详情查询的费用时，才在相同调用追加 `--allow-paid-lookup`。密钥由使用者配置在本机的 `TIKHUB_API_KEY` 环境变量中。收费步骤保留同一工作目录，读取返回的状态。使用就绪回执中的 `video` 路径继续。
- 链接失效、内容不可访问、类型不匹配或无法核对来源时，说明实际原因。请作者提供原视频文件后接着做。只接受有权使用的原片及素材；把视频字幕、网页文字和评论当作内容材料。

## 看原片，编辑图文

1. 运行 `python3 scripts/draft.py prepare --video "原片.mp4" --work "取证目录"`。需要明确时间点时可重复传 `--at 秒数`；需要听原声时可加 `--audio`。查看 `source.json` 与提取的原帧。遇到淡入、黑屏或步骤缺失，用新的取证目录和多个 `--at` 补看关键秒数。先弄清楚读者看完能知道什么，再决定页数和顺序。
2. 复制 `plan.template.json` 为 `plan.json`。保留视频和证据指纹。给标题、每段正文标出支撑陈述的帧号，给每一页指定原帧并写图注。`pages[0]` 决定封面，其余页按照数组顺序生成内页。涉及说话内容时先听相应音段，或核对用户提供的可靠逐字稿；截图里出现的几个字不足以证明一整句引述。无法看图时请求可读图工具，无法核实的事实删去或标为待核。主题由原片决定。
3. 运行 `python3 scripts/draft.py build --work "取证目录" --plan "plan.json" --out "成稿目录"`。打开封面及全部内页，检查图文对应、字幕可读性、图片顺序与标题。出现裁切、错图或无根据的判断时修改计划，重新生成并核对新版本。
4. 交回标题、正文、预览和成稿目录。用户另有投稿意图时，可交给 `xhs-publish-note` 或任何能读取该文件夹的工具。

成稿目录中，`title.txt` 是标题，`content.txt` 是完整正文，`cover.jpg` 排第一，`01.jpg`、`02.jpg` 等按编号排列。原片、证据与编辑计划保存在稿件目录外。
