# 小红书图文发布

首版验证环境为 macOS，本地验包要求 Node.js 22+。官网操作需要桌面 Chrome、npm 依赖和网络。

在此 Skill 目录执行命令，把稿件目录作为独立参数传入；路径含空格时加引号。命令回传 JSON 时，进度写入标准错误流，结果写入标准输出，进程非零退出表示出错。如果宿主支持本地命令即可调用；远端宿主需要连接到持有素材、浏览器和会话的执行设备。

## 第一步，检查成稿

```sh
node cli.mjs check "./稿件目录" --json
```

纯本地检查只需要 Node.js。推荐输入为 UTF-8 的 `title.txt`、`content.txt` 和成品图片（例如 `cover.jpg`、`01.jpg`、`02.jpg`）。封面优先，编号内页依次排列。图片可统一放在 `images/`；选帧参考、预览拼图、原片和草稿另放一处。也支持旧版的标题/正文 TXT 中文文件名，以及用一级标题、正文及话题构成的单个 `post.md`。每篇只提供一种文案来源。格式规则以实际检查结果为准。

读回 `title`、`body`、`images` 和 `fingerprint`。只要求做稿或验包时，在这里交付即可。需要短标题时使用经确认的 `--title`，后续查询、提交均带相同值。

## 使用授权账号

首次需要连接官网时，在此目录执行 `npm ci`，并确认本机安装了 Google Chrome。使用者指定固定的本机账号键以及创作者中心显示的完整昵称。登录信息和账本默认保存在用户目录的 `~/.local/state/xhs-publish-note/`；多次调用和不同 AI 共用同一状态目录才能识别原账号及历史提交。首次部署可通过 `XHS_PUBLISH_STATE_DIR` 选择专用私有目录。

```sh
node cli.mjs login --account "本机账号键" --nickname "官网昵称" --json
```

若需扫码或验证，交由持有人操作本机官网窗口。重新授权时使用相同账号键。网页预览会把素材上传到创作者中心，可能产生草稿。用户要求网页预览时执行：

```sh
node cli.mjs preview "./稿件目录" --account "本机账号键" --nickname "官网昵称" --keep-open --json
```

`--keep-open` 会保留浏览器直至人工关闭；无人值守调用可省略。正式发布须取得本篇定稿与目标账号相符的明确授权，或检查已有、可验证且覆盖本次操作的长期授权。仅有链接、设备登录或稿件指纹都不等于发布授权。长期授权里的篇数、时段、审核规则等由调用方在派发每篇前校验；本 Skill 提供单篇执行和同稿防重。

```sh
node cli.mjs publish "./稿件目录" --account "本机账号键" --nickname "官网昵称" --confirm-fingerprint "本篇已获准的64位指纹" --submit --json
```

用户已经明确批准当前账号和这版稿件时沿用授权。内容变化后重新检查，按原授权范围处理。命令 `submitted` 表示官网已返回提交提示。接着核查这一笔任务：

```sh
node cli.mjs lookup "./稿件目录" --account "本机账号键" --verify-submission --json
```

向使用者报告「已发布」「审核中」或「平台状态待核」。断线或遇到历史提交记录时，先用 `status` 查看本地记录，再用上面的 `lookup` 核对。保留 JSON 回执。授权失效、验证页面、账号不符或上传控件无法确认时，按原稿和原账号恢复。平台结果不明时继续查同一条；人工核实且决定如何登记后，可用 `node cli.mjs --help` 中的 `reconcile` 按原任务号记录处理结果。
